Portfolio Builder — System Overview

Multi-tenant portfolio platform · React (Vite) + FastAPI + SQLite · Generated from codebase at portfolio/

1. What the system does

Users register with an email, password, and unique public slug. Each account owns exactly one site. They edit content in a dashboard, publish it, and visitors open /u/<slug>. Contact forms store messages per site.

1. Register /register · email + password + slug
→
2. Edit /dashboard · profile, hero, work…
→
3. Publish theme + published flag
→
4. Live site /u/:slug · public portfolio

2. Architecture (layers)

Frontend — React 19 + Vite + React Router localhost:5173 · Pages: Landing, Login, Register, Dashboard, SitePage
Components: Hero, About, Projects, Experience, Skills, Contact, Nav, Footer…
Dev proxy: /api → http://127.0.0.1:8001 (or 8000)
Backend — FastAPI (Uvicorn) localhost:8000/8001 · Router prefix /api
Modules: main.py, routes.py, auth.py, db.py, schemas.py, config.py
Database — SQLite backend/data/portfolio.db
Tables: users, sites, sessions, messages

3. Auth & identity workflow

Browser
POST /api/auth/login → Stores cookie portfolio_session → Later requests send cookie (credentials: include)
API
verify password → create_session(user_id) → Set-Cookie HttpOnly → current_user dependency
SQLite
users → sessions (token, user_id, expires) → sites WHERE user_id = ?
Dashboard does not take a slug from the URL. The session cookie identifies the user; the DB returns that user’s single site (and its slug).

4. End-to-end workflows

A. Registration

POST /api/auth/register → create_user → blank_portfolio + create_site → session cookie → navigate /dashboard

B. Dashboard load & save

GET /api/dashboard/portfolio + GET /api/dashboard/messages → fill React state → PUT /api/dashboard/portfolio → PATCH /api/dashboard/settings

C. Public site & contact

/u/:slug → GET /api/sites/{slug} → Hero, About, Projects… → POST /api/sites/{slug}/contact → messages table

6. Data model

users

  • id, email (unique)
  • password_hash (PBKDF2)
  • created_at

sessions

  • token PK → cookie value
  • user_id, expires_at

sites (1 per user)

  • user_id UNIQUE · slug UNIQUE
  • theme (night | ice)
  • published 0/1
  • portfolio_json — full document

messages

  • site_id, name, email, message
  • created_at

10. Key constraints

  • One site per user (sites.user_id UNIQUE)
  • Slugs unique globally; 3–32 chars, lowercase, numbers, hyphens
  • Unpublished sites: 404 for public; owner can preview while signed in
  • Contact honeypot field website — if filled, silently discarded
  • Demo seed: mahi@demo.local / mahi1234 → /u/mahi
